## ประเด็นที่ไม่เคลียร์: solution + assumption

### A7-10 · เอาตัวเลือก "สั่งรับเรื่อง" (ม.28) ออก
- คำถามเดิม: เอาออกทั้งหมด หรือซ่อนไว้ตั้งค่าเริ่มต้นเป็น "รับเรื่อง"?
- Solution: ซ่อน `#m28Card` ในหน้าเลขาฯ ทุกสำนวน ตัวเลือกแรก "สั่งรับเรื่องไว้พิจารณา" ถูกเลือกไว้ `m28Selected()` จึงคืน `ACCEPT` เสมอ
- Assumption: ยังไม่ลบทางเดิน ม.28 ไม่รับ / จำหน่าย ออกจาก logic เพราะลบแล้วต้องแก้ลำดับสถานะ (นอกขอบเขตที่อนุญาต) — ถ้ายืนยันให้ลบ ค่อยตัดโค้ดในรอบถัดไป

### A7-13 · แจ้งเตือนเมื่อส่งคืน
- คำถามเดิม: ผู้รับผิดชอบสำนวนเป็นผู้ใช้ กจ.5 จะรับแจ้งเตือนทางไหน
- Solution: ทั้ง 3 จุดส่งคืน (รองเลขาฯ, เลขาฯ หน้าจอ 213, เลขาฯ หน้าจอชี้มูล) มีเหตุผล + แนบไฟล์ (ไม่บังคับ) หลังส่งคืนสำเร็จเรียก `notifyOwnerOnReturn()` ซึ่งบันทึก event `RETURN_NOTICE` (ผู้รับ, เหตุผล, ไฟล์แนบ, ช่องทาง) และ toast แสดง "แจ้งเตือนถึง <ผู้รับผิดชอบสำนวน> แล้ว — เหตุผล … · ไฟล์แนบ …"
- หน้าจอชี้มูลเดิมไม่มีช่องแนบไฟล์ เพิ่ม `#swal-file` ให้เหมือนอีก 2 จุด
- Assumption: ช่องทาง = แจ้งเตือนในระบบฝั่ง กจ.5 + อีเมลผู้รับผิดชอบสำนวน (รอตกลงกับทีม กจ.5) ถ้าบันทึก event ไม่สำเร็จ ไม่ยกเลิกการส่งคืน

### A7-15 / A7-16 · วิธีลงนามรายงานวินิจฉัยชี้มูลของประธานฯ
- คำถามเดิม: มติครั้งที่ 10 ให้ลงนามสด — ยังเก็บตัวเลือกลงนามในระบบไว้ไหม
- Solution: การ์ด "การลงนามรายงานวินิจฉัยชี้มูล" มี radio ① ลงลายเซ็นในระบบ ② เซ็นจริง แล้วอัปโหลดรายงานไต่สวนชี้มูลฉบับลงนาม
  - ② บังคับแนบไฟล์ PDF / PNG (ไฟล์ชนิดอื่นถูกปฏิเสธ, ไม่แนบ = เตือนและไม่บันทึก) มีกล่องยืนยันแสดงชื่อผู้ลงนามและชื่อไฟล์ ไม่เปิดกล่องลงนามดิจิทัล
  - ไฟล์อัปโหลดเข้า bucket `case-documents` + `tbl_res_attachment` (แบบเดียวกับไฟล์แนบอื่น) และบันทึก `signedRulingMethod` / `signedRulingFile` ใน `trr_resolution_data` และ event `SIGNED` (method `wet-upload`)
  - หลังลงนามแสดง "เซ็นจริงและอัปโหลดฉบับลงนามแล้ว (ชื่อไฟล์)"
  - สถานะถัดไปยังมาจาก `nextStatusPatchByResolution()` / `TRANSITIONS` เดิม (ทดสอบ 112 → 115)
- Assumption: ตั้งค่าเริ่มต้นเป็น ② ตามมติครั้งที่ 10 และคง ① ไว้เป็นทางเลือก จนกว่าจะยืนยันให้ตัด
